### R2-02 Published ECE is computed at the design base rate of a case-control sample; the artifact's "perfect calibration" criterion is design-dependent
- category: DISCLOSURE (owner-gated packet) · size: S · status: NEW
- **claim affected:** RESULTS.md:26 row 11 / CLAIMS.json claim 11 — "ECE wave-2 0.179 (wave-1 0.209)" and its stated interpretation ("uncalibrated ~0.18": `analysis/calibration_wave2.py:52-53`, `specs/calibration_scope.md` §1).
- **evidence:** ECE compares per-bin mean predicted probability to the observed fraud fraction of a sample whose prevalence was **fixed by design** (8/30 = 26.7% wave-1; 9/32 = 28.1% wave-2) — `analysis/calibration.py:25,38-40`, `analysis/calibration_wave2.py:20,32-34`. Under case-control sampling, the bin fraction estimates P(fraud | score, design), which differs from population P(fraud | score) by the sampling odds: a model perfectly calibrated to any realistic screening population (prevalence ≪ 27%) would show a *large* in-sample ECE here, and a model matching these bin fractions would be badly miscalibrated in deployment. The artifact's own criterion — `analysis/calibration.py:57` "완전 보정이면 fraud 비율이 예측 확률을 따라야 함" — is true only at the design prevalence. Neither `specs/calibration_scope.md` §1–§3 (ordinal demotion, small-N instability, expected overconfidence) nor row 11's limits states this; the row's hedges cover different failure modes.
- **direction:** the published conclusion ("does not function as probabilities", null-ish, no improvement) survives — at realistic prevalence the miscalibration would be worse, and the w1→w2 comparison is like-for-like (similar design prevalence). Scoping sentence, not a correction. Adjacent to, but distinct from, the dispositioned PR-AUC/base-rate item (B10 → DP-Q6): that concerns which metrics to compute for a prospective universe; this concerns what the already-published ECE can be read as measuring.
- **fix shape:** one sentence in row 11 limits (and/or additive clarification in `specs/calibration_scope.md` §2): "ECE is computed at the case-control design prevalence (~27–28%); it measures in-sample departure only and is not an estimate of deployment calibration error." Same owner packet as R2-01; CLAIMS.json sync; zero recomputation.

### R2-03 Power-analysis doc plans a two-sided AUC z-test while the registered primary inference is a one-sided mean-diff permutation test — mismatch undisclosed in the doc feeding DP-Q3
- category: STATS-DOC (buildable, additive) · size: S · status: NEW
- **claim affected:** queued measurement design — the DP-Q3 N-expansion decision, whose signed evidence input (D-P40, DECISIONS_PENDING.md:679-681) quotes these numbers as "현행 설계 충분(wave-1 0.832·wave-2 0.874)" / "심대 부족(0.285-0.320)".
- **evidence:** `tools/power_analysis.py:73-83` computes power for a **two-sided** z-test on **AUC** (Hanley–McNeil SE; `:116` records `"sidedness": "two-sided"`); `docs/POWER_ANALYSIS.md:52-65` publishes required-N and achieved power from it. The registered primary inference an expanded design would actually run is a **one-sided permutation test on the mean difference** (`analysis/stats.py:31-41`, `aaer_eval/statistics.py:37-47`; every published p in RESULTS rows 1–3 is this test). The doc's 한계 section (`docs/POWER_ANALYSIS.md:79-87`) discloses the HM approximation, distributional assumptions, case-control non-prospectivity, and non-propagated AUC uncertainty — but not the statistic or sidedness mismatch. Verified in passing: at A=0.5 the HM variance reduces exactly to the Mann-Whitney null variance (n_t+n_c+1)/(12·n_t·n_c), so the null SE is right — the mismatch is of test and sidedness, not algebra.
- **direction:** two-sided AUC planning is conservative relative to the one-sided registered test — required-N overstated, achieved power understated. The qualitative D-P40 reading (adequate vs 0.50, deeply underpowered vs 0.65) almost certainly stands; but an owner deciding N from this table should know the numbers price a test the repo does not run.
- **fix shape:** 2–3 sentence addition to the 한계 section naming both mismatches and their conservative direction. NO new simulation machinery (see c.). Additive doc edit; POWER_ANALYSIS.md is not frozen; INV-03 disclosure line.
