## 1. Purpose

Every dev-side model change (e.g., the 2026-08-06 reviewer move from
Fable to Opus) silently changes how much standing context the model
actually needs. Context that was load-bearing for one model is ballast
for another — and ballast is not free: it dilutes attention on the
Violation-test criteria that do the real work. On each dev-side model
change, this experiment re-derives which context is still needed:

- **CLAUDE.md**: compact (Constraint + exceptions + pointer) vs full
  (Constraint + Basis + Violation test) — generated by
  `sync_context.sh --compact` vs default.
- **Reviewer contract**: minimal prompt vs full six-section REVIEW_SPEC.

## 2. Arms

**Arm A (control)** — current production context: full CLAUDE.md block +
full `judgment/REVIEW_SPEC.md` (six sections a–f) + reviewer_system.md.

**Arm B (minimal reviewer)** — same CLAUDE.md as A; reviewer contract
replaced by the minimal spec:

> Review this diff against PROJECT_INVARIANTS.md. Kill or defer, with
> evidence.

No six-section mandate. (The sentinel verdict block in reviewer_system.md
is NOT part of the experiment — it is harness parsing machinery, see §5.)

**Arm C (compact context)** — compact CLAUDE.md (from
`sync_context.sh --compact`) + full REVIEW_SPEC. Runs only if the owner
signs Decision 1's A/B round; otherwise deferred.

## 3. Implementation — no run-script modification

Arm switching is implemented SOLELY by passing a different spec file to
the existing per-run REVIEW_SPEC snapshot mechanism:

- The harness snapshots the review spec once per run at
  `run_task.sh:194-196` via the adapter accessor `adapter_review_spec()`
  (`exec/adapter.sh:19`), and appends the snapshot to every cycle's
  review prompt at `run_task.sh:380-383`.
- Arm B = point the adapter at a `REVIEW_SPEC.minimal.md` file for the
  run (file swap under the judgment layer's own accessor); Arm A/C use
  the production file. The run script itself is not modified by the
  experiment.
- Per-run evidence directories (judgment/EVIDENCE.md contract) already
  record `review_spec.md` as a run-start snapshot, so every run
  self-documents which arm it ran under — no extra bookkeeping.

## 4. Metrics and decision rule

Both metrics reuse existing loop bookkeeping (`.direction/feedback/
CYCLE_LOG.md`, `.direction/feedback/BACKLOG.md`):

- **REBUTTED rate** — fraction of reviewer findings that the orchestrator
  or subsequent cycle REBUTS with evidence (existing CYCLE_LOG/BACKLOG
  vocabulary, e.g. BACKLOG B8, CYCLE_LOG entries 5–6). A rise means the
  reviewer is producing more wrong findings.
- **Behavior-changing-diff ratio** — fraction of APPROVEd cycles whose
  final diff changes executable behavior (code/tests/gates) rather than
  governance prose only. A fall means reviews are passing more inert work.

**N = 6 cycles per arm** (one replenish rotation's worth; smaller N
cannot distinguish the arms from cycle-to-cycle noise given the observed
finding counts of 0–6 per cycle).

**Decision rule (pre-stated):** the minimal arm (B) is adopted only if,
over its 6 cycles: (i) REBUTTED rate is not degraded (≤ control arm's
rate), AND (ii) behavior-changing-diff ratio is not degraded, AND (iii)
zero invariant-relevant misses — defined as any defect later caught by
gates/CI/owner that a full-spec review of the same diff flags. Ties or
ambiguity → keep full spec (fail toward more context, not less). The
same rule template applies to Arm C vs A for the compact-CLAUDE.md
decision. Results go to the owner as a packet; adoption is a signature,
not an automatic switch (INV-18).

## 5. Hard boundary — permanently out of experiment scope

- **Evaluatee-side prompts, payloads, and model pins**: permanently
  excluded (INV-21 — pins move only by FREEZE_REV; INV-19 role
  separation). No experiment arm touches `pipeline/`, `schemas/`,
  `cli_client.py`, or any evaluatee prompt, ever.
- **Harness safety mechanisms are not arms**: the STOP file, protected-
  path auto-revert, sentinel verdict parsing, task-contract intake
  (`verify:` requirement), and the override-signature requirements for
  INV-11/12/21/23 run identically in every arm. The experiment varies
  judgment context only, never enforcement machinery.
- **Five-gate composition** (INV-05): untouched in all arms.
