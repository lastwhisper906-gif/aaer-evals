## FINDINGS (BACKLOG format, ranked by claim impact)

### R5-01 Tier-2 as documented cannot pass for any external reproducer — the acquisition section covers ~2 of 5+ required fetch tools, and pinned hashes of living SEC endpoints are unmatchable by any later fetch; neither limit is disclosed
- category: DOCS (reproducibility contract) · size: S · status: NEW
- **evidence:** REPRODUCING.md:95-99 states acquisition = "the two fetch tools in §3" (`fetch_xbrl_facts.py` + `fetch_primary_sources.py`). But the 538-file manifest those two tools must reproduce also contains `short_interest/shrt*.csv` (FINRA — fetched by `tools/fetch_short_interest.py`), `finra_schedules/` (Wayback snapshots — `tools/dissemination_schedules.py`), `reference/` (cik-lookup, company_tickers), `_aaer_index/`, and `_controls/` companyfacts (control-pool convention, `tools/control_screening.py`) — attribution logic for each family is visible in `verify_manifest.py:114-150`; none of those tools appear anywhere in REPRODUCING.md. Separately, `verify_manifest.py` full mode is fail-closed on **any** MISSING/EXTRA/HASH mismatch (`:207-232`), and the pinned targets include `data.sec.gov` companyfacts/submissions JSONs — cumulative living documents that upstream rewrites as new filings arrive. So a stranger who follows §2/§3 today gets a corpus that fails `make verify-full` twice over (hundreds of MISSING entries + hash drift on everything refetched), with no documentation that this outcome is *expected*, what it *means* (the manifest attests the owner's frozen corpus, not any fresh fetch — the docstring at `verify_manifest.py:1-15` frames it as disk-loss insurance, a purpose §2 silently repurposes as a third-party gate), or how to obtain the matching corpus ("available on request", REPRODUCING.md:98-99, is scoped only to blocked-egress environments and names no channel).
- **failure scenario:** a motivated reproducer spends hours fetching, runs `make verify-full`, gets a wall of `HASH MISMATCH`/`MISSING`, and files a failed-reproduction report — a false negative against the repo's central claim, caused by docs, not science.
- **fix shape:** honest-scope paragraph in REPRODUCING §2 (what a fresh fetch can and cannot reproduce: recomputed *values* comparable, *bytes* not; manifest = owner-corpus identity proof), complete the tool list (one line each), and name the corpus-request channel. Doc-only; no new machinery.
- claim: **reproduce-from-public claim** (README "Check it yourself"; REPRODUCING G2 purpose statement).

### R5-02 `verify-full` overwrites tracked artifacts *before* validating the corpus — a drifted/incomplete corpus silently rewrites committed results and then surfaces as "published numbers don't reproduce"
- category: CODE (Makefile ordering) + DOCS · size: S · status: NEW
- **evidence:** Makefile:33-39 order is `corpus-check` (existence only) → `baselines.py` → `stats.py` → `synthesis.py` → `calibration_wave2.py` → **then** `verify_manifest` → `verify-public`. The first four read `~/aaer-data` (e.g. `baselines.py:16-17` imports `screens.run_case`, the raw-XBRL PIT recomputation; REPRODUCING.md:102-105 says so for synthesis) and write **tracked** paths: `analysis/baseline_table.csv` + `baseline_details.json` (`baselines.py:76-82`), `analysis/results_stats.json` (`stats.py:242`), `analysis/synthesis.json`, `unified_table.csv`, and the README-linked `analysis/fig_memorization_doseresponse.png` (`synthesis.py:168-180, :223, :256`). - **fix shape:** move `verify_manifest` before the four recompute scripts in the `verify-full` recipe (pure reorder — all commands retained verbatim; the INV-05 surface loses nothing) + one REPRODUCING sentence: "verify-full rewrites tracked analysis artifacts in place; run it on a clean checkout and inspect `git diff` after."
