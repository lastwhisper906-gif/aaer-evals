### R4-01 The FB-01 blindness regression test verifies its own re-implementation of the filter, not the runner's send site — the pre-FB-01 bug shape can return undetected
- category: TEST (quality) · size: S · status: NEW
- **evidence:** `pipeline/test_payload_blindness.py:27-29` — `_render()` re-implements the allowlist filtering locally and every assertion (`:36-39, :49-51, :57-61`) runs against that local copy, keyed off the module constant, never off code the runner executes. The real send sites are `runner.py:130`, `runner_api.py:41`, `probe_runner.py:62`. Post-FB-01, `build_payload.py:186-192` has non-underscore keys exactly equal to the allowlist, so an exclusion-based regression at the send site (`{k: v for k, v in payload.items() if not k.startswith("_")}` — precisely the pre-FB-01 shape at old `runner.py:123`) produces byte-identical output on today's payloads: the blindness test, the fingerprint test (`test_fingerprint_idempotency.py:112-116`, which only compares hashes of the same fixture), and the runtime guard all stay green, because `EVALUATEE_FORBIDDEN_MARKERS` (`cli_client.py:50-54`) contains answer-key/canary markers but **no experiment markers** (`variant`, `perturb` are absent — deliberately, since `test_payload_blindness.py:19` polices them only test-side). The next non-underscore metadata key added to the payload then leaks to the model silently. FB-01's own fix shape (BACKLOG:29-31) promised "regression test asserting no experiment-marker key names or values **in the rendered user_payload**" — the shipped test asserts over `_render`, not the payload the runner renders.
- **failure scenario:** send-site filter drifts back to exclusion-based during any refactor → all 359 tests pass → a later `build_payload` change adds a non-underscore run-marker key → perturbed arm self-announces the experiment again, unnoticed until (at best) a manual runmeta audit.
- **fix shape:** one test in the established mock pattern (`test_fingerprint_idempotency.py:44-52` already runs `run_case` with `call_model` monkeypatched): capture the `user_payload` argument actually passed by `run_case`, using a fixture that carries an **adversarial extra non-underscore marker key** (e.g. `"variant": "perturbed"`), and assert parsed keys == `EXPECTED_KEYS` and no FORBIDDEN substring in the captured string, both arms. Same one test for `probe_runner` (capture precedent already exists at `test_probe_runner_v2ds.py:15-20` — it captures `user` but asserts only date-shift rendering). No new machinery; ~20 lines total.
- claim: memorization-control/perturbation claim (name-ID 21.9%, B3 attribution 0.147) — the claim FB-01/L-9 exists to protect.
